# Testing Write-up

For my testing strategy, I started with the utility functions since the cart depends on them. I gave each function its own describe block and wrote 49 tests. I focused mostly on edge cases like the discount cutoffs ($49.99, $50, $99.99, and $100), empty carts, zero and negative numbers, decimals, and bad quantities. After that I wrote 35 tests for the ShoppingCart component using React Testing Library and userEvent. These tests act like a real user by adding items, trying invalid input, removing items, changing quantities, and clearing the cart, then checking what shows up on the page. All 84 tests pass, with 98% statement, 100% branch, 95.23% function, and 97.87% line coverage. The only line not covered is the one in App.tsx.

I learned that testing right at the boundaries is really useful, because a small mistake like using > instead of >= would only show up at the exact cutoff. Those tests also showed me that a $100 cart is actually cheaper than a $99.99 cart because the discount is bigger. I also learned to use toBeCloseTo for decimals since floating-point math isn't always exact. The biggest thing I learned is that high coverage doesn't mean the code is correct. If you clear a quantity box, the cart shows $NaN because NaN gets past the quantity < 1 check, even though my tests had already covered that line. We were supposed to keep the component code as given, so I wrote a test that records this behavior instead of fixing it.
